# 给开发者／编程智能体的实施任务书

下面的提示词可用于启动后续实现工作。本仓库本身仍是规格与提示词包。

## 可复制提示词

请为 Pal-AI-Lab/Coopanion 实现可验证的有限分层记忆。先阅读本仓库 README、docs/design.md、docs/coopanion-integration.md、config/policy.example.json 与 REFERENCES.md，再检查目标 Coopanion 和其 vendor/cortico 的实际提交及仓库开发约定。实现变化时遵循实际仓库规则，不假定旧快照的接口仍有效。

目标行为：
- 每轮用户与助手的对话原文都进入宿主管控的冷档案；即使只是一句寒暄、没有生成记忆卡，也保留原文。用户明确要求删除的内容除外。先迁移现有可读取的旧对话；已经丢失的原文不能从摘要复原。
- 少量近期、反复提及、用户明确进行中的记忆进入 hot 候选；每次只注入相关且预算内的内容。
- 可选启用 docs/persona-continuity.md 与 config/continuity.example.json：在原 hot960 内预留状态320 / 近期细节320 / 话题事实320。稳定角色底座持续保留，跨午夜、重启和 handoff 先恢复已提交的当前状态；慢变风格与短期状态分别处理，不让单次冷召回或重试改写性格。
- 实现 docs/vector-ranking.md 与 config/vector-ranking.example.json：存储事件向量引用，按当前问题计算关联度；热区同优先级采用向量关联、时间衰减、有效提及频率的综合排序，Top N 仍服从原条数/主题/token和状态子额度。冷召回不使用年龄或最近提及衰减，不先截取最新记录；保留精确线索索引与无兼容向量时的降级，向量计算和重排成本入账。
- 低频记忆冷存并保留可追溯来源，不因时间衰减删除原始记录。
- 读取 docs/graduated-cooling.md，普通事件按“近期细节 → 合格短摘要 → 冷库”选择可见表示；低频和容量处理先精简再退出，保留必要的当前话题与未完事项，所有表示仍受原有硬预算。限制调用、更正和删除立即生效；冷却不改写稳定性格与当前相处基线。
- 读取 docs/cold-storage-index.md，实现类型、事件时间、地点、人物、物品、话题的多入口索引。地点等单一有效线索可先筛范围，候选歧义时用极短卡片请用户补充，随后组合条件；完整目录不送模型，跨分区仍执行全局候选与召回预算。
- 默认 cue_only 只在真实用户提供具体线索或有效同话题追问时准许冷检索。可选主动模式须用户明确开启，由宿主按当前情绪与话题签发本次互动的有限 proactive_scope；情绪相似不证明原因相同。“问到再说”、更正、删除、身份/范围限制及须具体线索才能调用的敏感内容优先；定时事件、工具、截图和助手联想不能自行授权。
- 可选实现 docs/proactive-memory.md、config/proactive.example.json 与 prompts/proactive-companion.zh.md。将检索许可、事实依据、是否提起分开；主对话正常回复时决定 use / ask / silent，不为每条候选另开模型调用。最终最多2条事件和可选1条最多96 token的反思，连同来源、候选卡及封装仍共用3条/480 token召回额度；不能挤占状态与近期细节的保留空间。
- 反思使用独立存储与 prompts/reflection-maintainer.zh.md，只根据获准的新增真实近期经历提出变更。用户自述、可观察经历、助手承诺、反思和猜想保留类型、来源、有效期与不确定性；猜想不能变事实，旧反思不能作新反思的事实来源，助手自己的话不能提高热度或改写稳定性格。空闲不翻冷库；更正、删除与限制立即撤销相关派生内容。
- 后台反思维护每次最多2项变更；整条维护链每天最多2次调用尝试，失败重试也算，至少间隔6小时；每次完整输入最多2000/输出上限300 token，每日4000/600。辅助模型、嵌入、分类与重排共用账本，无新增已完成事件就不调用。调用前预留预算，跨重启保留水位、幂等键与单任务锁；无法可靠计数或限制输出时关闭后台模型维护。这些是待实测的示例参数。
- 单次召回不自动常驻；只将用户有效提及计入热度，防止复述、重试和重复总结造成自我强化。
- 用户能固定、纠正、取消固定、要求问到再说和真正删除。各动作保持明确、不同的语义。

工程要求：
1. 为存储、用户提及统计、线索门控、预算选择、实际请求投影建立清晰边界。现有挂点不足时提出并实现必要的 Cortico 上游接口，不直接假装存在接口或长期补丁 vendor 副本。
2. 默认预算按策略文件：记忆总块 1600，pinned160 / hot960 / recall480，各自不可借用；近期历史另外2000，最多6个完整交互单元。模型完整上下文和输出预留另行校验。没有可靠计数器时明确报告为保守估计，不能称硬 token 保证。
3. 每轮双向对话原文先归档，短记忆卡只是带来源的派生摘要或指针；原始日志继续持久化，发给模型的内容按政策投影。覆盖 PARTNER、handoff、旧召回工具结果、助手复述、重启与分支恢复等回流路径；不得一边冷存一边继续全量重放旧session。
4. 冷档案通过受控适配器访问，阻止 read/search/exec/扩展等通用路径绕过门控。保持工具调用与结果成对，保留 provider 必需的当前轮推理结构。事务不能安全压缩时停止叠加，不拼出非法请求。
5. 固定角色与工具前缀保持稳定；记忆快照在事务边界替换，避免每轮追加。缓存与缩短历史的取舍通过测量决策。
6. 复用已有调用与缓存账本，增加用户交互归因和记忆构成；把抽取、检索、嵌入、重排、维护、重试全部纳入成本。不要只报告一个短请求而漏掉后台成本。
7. 以 examples/dialogue-archive.json 和 examples/scenarios.json 为验收基线，扩展真实接口测试。使用隔离的合成数据，不读取或上传用户真实档案。再按 examples/vector-ranking-scenarios.json 检查跨年代召回、事件关联度与情感状态保护；启用主动模式时按 examples/proactive-scenarios.json 检查默认不开启、授权范围、情绪不等于原因、保持沉默、拒绝后的冷却、更正删除、反思不变事实，以及失败重试/并发/重启后的共用预算。结合真实模型盲评跨日表达与情境变化，不能把角色状态算式当作真实感已验证。验证未制卡对话仍归档、热度、冷存完整性、门控、预算、更正删除、隔离、工具协议和实际发出请求。

交付：可审查的改动、迁移与回退说明、自动化验证结果、同条件 A/B 评估脚本及报告。报告区分代码实现、结构检查、真实模型测试和计费实测；没有测到的效果明确标为未验证。引用已有项目，不宣传首创或预定节省百分比。此次实施任务不包含公开发布、向上游提交或运行用户生产环境。
