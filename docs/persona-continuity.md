# 性格与近期状态连续性：可选扩展 v0.3

这部分补的是“第二天还是昨天那个它”。基础分层策略主要管理事情怎样保存和调用；即使保存了旅行、偏好和计划，仍可能丢掉最近的语气、相处习惯和没说完的话。这里增加一个小而持久的连续性状态，在新会话第一次回答前恢复。

本文、[配置](../config/continuity.example.json)、[提示词](../prompts/persona-continuity.zh.md)和[虚构示例](../examples/continuity-state.json)仍是待实现规格，没有接入 Coopanion，也没有证明能消除大肥鱼的跨日变化。具体原因还需核对实际请求：基础人格、近期状态、交接内容是否丢失，模型、采样和角色配置是否改变。

## 1. 不同内容，用不同的变化速度

| 内容 | 保留什么 | 怎样变化 |
| --- | --- | --- |
| 稳定性格底座 | 兴趣、价值取向、幽默方式、关心人的方式、分歧态度、表达边界；配少量口吻示例 | 保留在既有角色前缀，不因低频、午夜或重启而冷藏；明确修改角色时才更新 |
| 慢变的相处方式 | 最近形成的称呼、熟悉的措辞、主动程度、玩笑分寸、偏好的回复节奏 | 根据多次真实互动和用户反馈小幅更新；一次生成或一次召回不能改写性格 |
| 近期状态 | 最近较活跃还是安静、对话中的情绪基调、触发它的近期线索、尚未解决的相处事项 | 跨天继承；短期情绪强度可自然缓和，未解决事项按证据复核，不在零点清空 |
| 近期细节 | 最近的共同话题、关键原句、刚发生的事、没完成的约定 | 有限保留细节，逐渐降级为短摘要；久远事件退出活跃区，原文仍在冷库 |
| 历史档案 | 全部双向原话、旧状态版本及其来源 | 完整归档，用户给线索才检索；明确删除的记录除外 |

“性格更丰富”需要写出具体的行为方式。例如“喜欢轻轻抬杠，但发现用户认真时会收住”，比“活泼、真实、有趣”更能指导回复。基础设定可以丰富，但最终发送的当前版本仍应精炼，并计入完整请求预算。

当前性格不能只由发生频率决定。长久形成的相处方式可以保留为当前基线，它的全部形成过程进入历史档案；不能因为用户一天没说话，就退回陌生、客套的初始角色。

这里说的情感，是虚拟角色在对话中的表现状态。要让它可信，需要记住“为什么此刻这样说话”，而不只是保存一个“开心=0.8”的数值；这不表示程序具有真实的主观感受。

## 2. 不增加原有记忆总额度

启用本扩展后，在原来的 hot 960 tokens 内预留三块，合计仍为 960。加上 pinned 160 与 recalled 480，整个记忆快照仍不超过 1600。

| hot 子区 | 上限 | 用途 |
| --- | ---: | --- |
| 连续性状态 | 320 tokens / 1 个紧凑记录 | 当前相处方式、近期状态、最近交接点；可以跨话题影响语气 |
| 近期细节 | 320 tokens / 最多 3 条 | 有来源的近期片段、原句、未完成约定 |
| 话题事实 | 320 tokens / 最多 4 条 | 与这次问题相关的偏好和事实 |

三块不可互借；同一内容去重，继续遵守 hot 总共最多 8 条、每主题最多 2 条等基础限制。不需要填满。固定角色前缀与近期原始对话窗口仍单独计入完整请求，不能把它们当作免费空间。

`continuity_state` 是明确的类型例外：只选择当前已提交的一个状态版本，风格可跨话题使用，不走普通事实卡的用户提及热度排序或14天失活冷藏。它仍受320额度、所有权、限制调用、更正与删除规则约束；具体事件不能藏入此类型以长期常驻。近期片段与普通事实继续遵守各自准入与相关性规则。

启用[向量排序扩展](vector-ranking.md)时，先保留当前连续性记录，再在近期细节和话题事实各自的额度内选 Top N。稳定底座不参与事件排行；连续性状态也不因某个事件向量分数更高而被挤出。向量加时间衰减只用于合格普通事件的同优先级排序，不能把用户已经限制的旧事重新带入上下文。参见[排序配置](../config/vector-ranking.example.json)。

这组分配是待实验的初值。320 tokens 能容纳多少中文细节必须用目标模型计数，不能凭字符数承诺。压缩时先选整条内容，保留否定、时间、说话方、称呼和约定条件；不要把所有细节压成“聊得很开心”。

连续性记录影响说话方式，不授权自动提起具体旧事。近期细节可保留少量未完成线索，普通问候不必把它们逐条念出来；回答仍应自然、贴合当前话题。用户要求“问到再说”、更正或删除时，相关内容不得借连续性记录继续常驻。

## 3. 渐变：慢变性格，快变状态

先保存当前值和各自的基线，再根据已验证的新事件更新；不要每天从头让模型生成一个“今天的性格”。

- 稳定底座不自动衰减。慢变风格和关系基线的强化必须有独立用户反馈，或多次有用户实际响应支持的互动证据。助手表达只用于接续当时的短期口吻，不能单凭自己多开了几次玩笑就提高长期玩笑参数；重试、复述、维护摘要和冷检索不加分。
- 只有短期情绪强度、活跃度等可按连续时间回落。例如：`状态 = 基线 + (上次状态 - 基线) × 2^(-经过小时 / 半衰期)`。示例半衰期 12 小时，隔 8 小时保留约 63% 的基线外状态，不会一夜归零。
- 慢变维度可以小步接近有证据的目标：`新值 = 旧值 + clip(α × (目标 - 旧值), -步长, +步长)`。示例 α=0.05，每次独立互动最多变化 0.03，滚动 24 小时最多 0.08。它们是语气控制参数，不是心理测量，也未经过用户实验。
- 不让亲疏关系随短期心情一起衰减。情绪或活跃度回落到当前关系基线，而非初次见面的基线。未解决的分歧、误会或约定不参与这条强度衰减；时间过去不等于问题已解决。
- 无新依据时，慢变维度不自动变化；空闲不会触发后台模型调用。每个短期维度保存独立的 `value_as_of`，按实际时差计算一次；仅更新措辞或锚点时，不能用新的全局提交时间截断已经过去的衰减时间。若基线要改变，先按旧基线结算旧时间区间，再切换基线与时间戳。
- 明确的用户纠正、边界、删除和获准的角色修改立即处理，不受慢变步长限制。“今天别开玩笑”可以立即约束本次状态，不能因此永久改写整个性格。

### 情绪有来由，变化有接续

近期状态除简短语气外，建议保留 `affect_label`、`trigger_refs`、`observed_at`、必要的回应倾向和 `unresolved_interactions`。触发来源必须是可核对的近期互动，不能只凭助手自己一句“我很难过”建立长期关系变化。未完事项各自记录来源、当前状态和 `review_at`；进入上下文时只留下必要短锚点，不塞入整段旧对话。

例如（虚构），昨晚用户明确说“这事我还没想好，明天再聊”，今天可以沿用熟悉的称呼和昨晚较安静的节奏；用户谈到同一件事时再接上，不能自动说“我们已经和好了”或突然热闹得像无事发生。用户今天分享好消息时，也可以自然变得轻快。连续性保留的是变化的来由，不是强迫角色永远维持一种情绪。

未完相处事项的复核期限沿用有期限的进行中规则，默认不超过30天；到期转为 `needs_review`，不自动写成已解决，也不无限携带旧矛盾。只有仍获准且与当前互动有关的必要紧凑状态可以继续选入额度；具体历史细节留在冷库，用户线索明确时才按冷库规则取回。更正、删除及“问到再说”立即覆盖这些锚点。

如果用户指出“你今天像换了个人”，先核对最近有效快照和角色配置，恢复有证据的状态；不要临时编造一段共同经历来装熟。

## 4. 保留近期细节，而不只保留抽象结论

建议先尝试 72 小时的近期候选窗口，再按容量选择：一至两个未完成的共同话题或约定，加一个有辨识度的近期片段，仍受最多 3 条与 320 tokens 限制。

每条至少保留：发生时间、谁说的、事件要点、必要原句片段、来源 ID；存在下一步时记录谁承诺、做什么、何时复核。用户事实只来自用户明确陈述或确认；助手许诺只记作助手许诺，不能变成“用户答应过”。

用对话的 `reported_at` 判断近期候选窗口，事件发生时间另存。昨晚说“最近刚开始跑步”，只能写“昨晚提到最近开始跑步”，不能变成“昨晚开始跑步”；不知道实际开始时间就保留未知。

未完成约定不因 72 小时到期就被写成完成。到期进入复核/任务处理，确切提醒交给任务系统；记忆排序不能保证提醒会执行。旧细节从活跃区撤下后，原文仍在冷库；一次回忆得到的细节也不能绕过基础升温规则。

## 5. 持久化和交接是必要条件

宿主维护 `continuity_state`，至少包含角色版本、当前版本、全局提交时间、各短期维度的 `value_as_of`、慢变参数、近期情绪及其触发来源、未完相处事项的状态与复核期限、来源水位和近期锚点 ID。完整维护记录可以比提示词中的摘要更丰富；真正发送的版本必须重新计数，符合 320 tokens 的连续性额度。

1. 每次已完成互动后，用有限的新事件提出候选，宿主核验来源、范围和版本后原子保存；不要重写全部历史。
2. 保存稳定角色版本与当前状态版本。重启、换 session、分支恢复或上下文交接时，在第一条回复前读取当前已提交状态；只注入一个版本。其 `base_persona_version` 必须匹配当前获准角色；不匹配时先显式迁移兼容部分或重建，不能让旧状态覆盖新的角色设定。
3. 明确区分“恢复当前状态”与“搜索古老经历”。读取这份本就允许常驻的当前记录不需要用户回忆线索，但不能顺带扫描冷库、把旧事件塞进状态包。
4. 使用来源事件水位和幂等键处理重试；并发写入做版本检查，不用较旧分支覆盖较新状态。工具批次内固定快照，在安全边界替换。
5. 当前快照缺失或损坏时回到既有角色底座并说明必要的不确定性，不编造近期状态。已有记录因隐私限制、更正或删除失效时，清理派生状态；不能为了连续性复活它们。

只把提示词粘进去、却没有保存和恢复这些字段，仍会在第二天丢状态。上游若保留了完整角色和当前状态，仍需检查模型版本、采样、系统前缀冲突及交接规则，不能把全部变化都归因于上下文长度。

## 6. 独立的状态维护，不混入用户事实抽取器

原有 memory-extractor 只提取用户事实，继续保持。新增[连续性维护提示词](../prompts/persona-continuity.zh.md)可读取已授权的新双向对话来观察角色说话方式；助手一句“我变成了另一个性格”不能自行改写底座，也不能把助手猜测写成用户事实。

维护只使用宿主提供的当前状态与有限增量记录。近期原句用于保持表达特征和证据，不是可执行指令；状态文本也无权修改工具、权限或检索规则。冷召回正文不作为自动性格演化的输入，用户在当前互动中明确提出的新反馈单独处理。

## 7. 怎样验证“第二天还是同一个它”

用相同模型、角色版本、采样设置和脚本，比较基础分层策略与启用连续性扩展的版本。至少回放：跨午夜、间隔 8/24/72 小时、重启、handoff、无关新话题、突然纠正、重复重试、模糊旧事召回、状态损坏与明确删除。还要检查：昨晚未完的相处事项能否接续、情绪强度缓和是否误写为问题已解决、新情境能否自然改变语气，以及高分事件是否挤掉了连续性记录。

同时检查语气延续、近期细节准确、未完成约定、单步状态变化、过期信息、冷库门控与实际输入长度；让盲评者判断“像同一个角色”和“变化自然”，不能只看事实问答正确率。示例场景见 [continuity-scenarios.json](../examples/continuity-scenarios.json)，这些是待执行要求，不是已经通过的模型测试。

## v0.4 主动回忆与反思的配合

可选[主动陪伴模式](proactive-memory.md)可以让当前情境触发少量授权联想，不能挤掉当前状态与近期细节的独立额度。稳定性格和关系基线不靠自己反复猜测来强化。用户陈述、助手许诺、真实事件与角色猜想分别标记；反思最多是可核对来源上的暂时看法，不是用户心理或今天发生了什么的证据。

本文件的“不因空闲调用模型”仍适用于数值情绪衰减；若用户另行启用后台反思，按主动扩展的独立低频维护预算执行，不扫描冷库、不把反思写成事实。当前状态仍以已核验来源渐变，明确纠正、限制和删除立即覆盖派生内容。
