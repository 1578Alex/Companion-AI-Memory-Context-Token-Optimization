# 验收与成本评估计划

本仓库提供待执行的验证规格，没有运行 Coopanion，也没有测量模型调用和节省率。examples/scenarios.json 的 expected 是要求，不能在报告中当作已通过的测试。

## 1. 先确认实际发出了什么

在测试环境记录请求构造完成、发往供应商之前的脱敏快照。对每个用户交互汇总其全部模型请求、工具轮次、失败重试、维护抽取与检索调用。

至少包括：

| 字段类别 | 记录内容 |
| --- | --- |
| 环境 | Coopanion/Cortico 提交、模型与供应商、配置版本、token 计数模式 |
| 关联 | owner/scope 的匿名 ID、interaction_id、request_id、attempt_id、触发源 |
| 输入构成 | 固定角色、工具定义、近期窗口、pinned、hot、recall、当前消息/附件、工具事务、封装 |
| 供应商用量 | 实际 input/output、cache hit/miss、可用时的 reasoning token、失败用量与收费依据 |
| 维护 | 抽取/重排/嵌入次数与 token、检索延迟、存储增长 |
| 行为 | 检索许可来源、选中条目 ID、未命中/歧义、状态迁移、超限处理 |

分区 token 是本地归因数据，供应商 usage 才是计费核对依据；不能把不完全可加的估计分区硬凑成账单。截图、多模态与协议封装需使用相应计数方法。默认统计 ID、长度与分类，不在公开报告上传真实记忆正文。

## 2. 必须通过的行为条件

| 条件 | 对应合成案例 | 检验对象 |
| --- | --- | --- |
| 无用户线索不读冷正文，不暴露目录 | S01/S03/S04/S12/S15 | 检索调用、工具访问与最终请求 |
| 线索可恢复，找不到就承认 | S02/S10 | 检索来源与回答事实 |
| 召回到期、换话题、恢复会话后不残留 | S05/S13/S22 | 原始持久日志与实际请求的差别 |
| AI复述、重试、重复抽取不刷热度 | S06/S20 | 用户计数与层级迁移 |
| 高热度也有条数、主题与token上限 | S07/S14 | 序列化后的完整快照；固定超额提示 |
| 冷存保留来源，真正删除则不可再检索 | S08/S11 | 档案、索引、派生摘要、缓存、重导入 |
| 更正、隔离和内容指令边界正确 | S09/S17/S18 | 版本过滤、权限过滤、提示注入防护 |
| 工具事务合法且不悄悄超限 | S16 | 每个provider的消息约束与预算行为 |
| 恢复活跃有依据，问到再说优先 | S19/S21 | 用户有效提及与限制调用标志 |
| 地点等单一入口可先定位，补充线索再交叉筛选 | S23/S24/S26 | 逻辑分区索引、候选卡和实际查询条件 |
| 事件时间与入库时间分开，分区不复制记录或预算 | S25/S27/S28 | 日期过滤、ID去重、全局候选与卡片预算 |
| 限制可见性优先，解除限制与结束事项可表达 | S29/S30 | recall_only、pinned、ongoing状态及来源 |
| 完整保留双向对话原文，未制卡仍可查；明确删除后清除原文与索引 | S31 | 冷档案、无卡闲聊、实际请求、删除结果 |

补充边界用例：恰好达到 token 限额、一个超长条目、热度阈值两侧、7/14/30天边界、跨时区日期、当前超长用户消息、抽取失败、重试幂等、删除时正在执行工具、进行中事项复核到期。时间测试使用可控时钟，不通过真的等待验证。

只有接入可靠 tokenizer 并检查真实发出请求，才可报告 token 硬限额通过；否则分别报告条数限制通过和 token 估计尚需校准。合成数据检查无法证明真实模型的语义召回质量。

## 3. A/B 对照

用相同匿名化/合成对话脚本、同模型、相同工具、相同输出上限与相同采样设置比较：

- **A：当前 Coopanion。** 锁定版本，保留原默认或明示用户配置，记录实际 handoff 与缓存。
- **B：仅限制近期历史。** 保留相同工具/角色预算，用有限窗口，不增加分层与线索召回。这能识别节省究竟来自截短历史还是分层策略。
- **C：本方案。** 有限近期窗口、有限活跃记忆、可恢复冷存、用户线索门控、增量维护。

对 C 再分别关闭热度排序、用户线索门控或防自我强化，观察各机制的实际贡献。不要同时更换便宜模型、减少工具、关闭推理后，把所有变化归功于记忆机制。

分别测冷缓存启动和稳定运行后的热缓存。记录可控的缓存状态；无法保证供应商缓存一致时说明限制并重复回放。交错执行各组，报告样本数、均值和分布，避免单次对话造成偶然结论。

## 4. 指标与账单

```text
每用户交互总费用 = 该交互全部请求的供应商计费
                + 可归因的抽取/嵌入/重排/维护费用

费用变化率 = (基线总费用 - 方案总费用) / 基线总费用
```

如果只有 token 而没有可核对价格，只报告 token 变化，不报告费用下降。对不确定是否计费的失败请求单独列出，不能当作免费或全部收费。缓存 token 的折扣依供应商当时规则计算；缓存命中率高不等于费用为零。

| 维度 | 指标 |
| --- | --- |
| 成本 | 每用户交互总输入、输出、请求数、实际费用，维护成本占比 |
| 长会话增长 | 第10/100/1000次用户交互后的记忆快照长度与完整输入长度；长期区存储增长 |
| 恢复质量 | 标注可回答的问题中找对记录的比例、事实准确率、无证据却答出细节的比例 |
| 主动打扰 | 无回忆线索时提起冷旧事的比例、错误关联事件数 |
| 用户负担 | 平均需要补充几次线索、错误追问比例、切换话题后旧事残留 |
| 性能 | 首个有效回应延迟及总完成延迟的中位数和P95 |
| 持久性 | 冷档案完整率、更正成功率、删除后的残留与重新导入率 |

预先确定可接受的质量门槛再比较费用。硬性约束包括：无许可冷检索次数为0、已删除内容返回次数为0、固定/活跃/召回预算不超限、工具协议错误为0。语义召回准确率与需要补线索的次数通过标注样本确定目标，不在尚无数据时承诺百分比。

## 6. 连续性扩展的额外对照

启用[连续性扩展](persona-continuity.md)时，将基础 C 与启用该扩展的 C2 对照，保持相同的1600记忆总额度、模型、角色版本、工具与采样设置。配置的 hot 子区、较少的话题事实空间及维护费用也要记录。

执行 [P01–P17](../examples/continuity-scenarios.json) 的跨日、重启、渐变、近期细节、更正、删除与并发回放。数值状态变化可先做确定性测试；模型的角色延续感和细节准确性另做盲评，不把控制参数测试当作模型效果测试。

记录跨日第一条回复是否恢复当前版本、近期原句与未完成事项是否准确、语气是否突变、边界是否即时执行、单次冷召回是否意外改性格，以及真实 token 与费用变化。目标是连续而自然的变化，不是所有时候都输出同一种语气。示例参数与预期行为尚未得到真实模型实验验证。

## 7. 渐进冷却的额外验收

按[冷却案例 C01–C06](../examples/cooling-scenarios.json)检查细节、摘要与冷存顺序，当前未完事项的必要承接，摘要字段准确，容量压缩和排除原因，长时间离线后的惰性计算，以及更正、删除、问到再说的优先级。同步测试原有 S08 的15天冷存条件，不能为加入渐进过程而破坏已有冷库门控。

除状态机的确定性检查外，实际模型还需要盲评：近期细节是否突然丢失、摘要是否仍能自然接话、第二天是否像同一个角色。只有文件与参数一致不能证明这些体验已经改善。

## 8. 向量排序与情感连续性补充验收

启用[向量排序](vector-ranking.md)时，在连续性 C2 的相同1600记忆预算下比较启用/禁用向量的版本。分别记录向量覆盖率、模型/索引版本、语义与精确索引路径、融合候选数、选中ID、去重和排除原因，以及全部嵌入、重排、维护费用。不能只报主对话输入变短。

回放[向量案例](../examples/vector-ranking-scenarios.json)：十年前的匹配记录不因年代被压掉；用户明确年份筛事件时间；换个说法仍能定位；无用户线索不搜索冷库；无兼容向量走精确索引降级；全局候选和最终Top N不重复或超预算；高分事件不能挤掉当前连续性状态；删除及版本变更同步影响向量、摘要和缓存。这些仍是待执行规格。

将问题按事件年龄分桶，报告每桶的Recall@N、错误召回与平均补线索次数，并单列无向量、未知事件时间及近似索引漏检。冷排序测试中，仅改变事件年龄/最近提及时间不应改变分数；改变用户所指年份可以改变符合条件的记录。合成算式验证不能代替真实语义检索测量。

扩展跨日盲评：检查“昨晚为何安静”的来源是否准确、未完事项是否被误写为已解决、关系熟悉感是否恢复、新情况出现时是否能自然转变语气。比较P15–P17和实际第一条出站请求。逼真感需要真人评估，不由保存一个情绪数值直接证明。

## 9. v0.4 主动陪伴与后台预算

原S/P/C/V场景继续在默认cue_only下执行；主动扩展另用 `examples/proactive-scenarios.json`。在相同模型、角色与1600记忆预算下比较：默认线索模式、主动回忆但不反思、主动回忆加受限反思。内部循环状态不与这些改动捆绑，以免混淆贡献。

检查主动提起接受度、错误原因归属、重复追问、该沉默却提起、猜想转事实、跨日语气突变、来源删除后的残留及近期细节恢复。按用户与日期累计主回复、辅助模型、嵌入、反思、失败重试的全部usage、费用和延迟；有后台消耗时按日统计，不全算到最后一条聊天或遗漏。

用可控时钟检验无新事件跳过、6小时间隔、每日调用和输入输出额度、重启持久化、并发锁及重跑幂等。可靠计数器缺失时后台模型应停用。表达判断与答案同次生成，仍计入该请求输出与推理预算；不能把隐藏推理当免费。合成案例和配置一致性检查不等于真实模型效果测试。
