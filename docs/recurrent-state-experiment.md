# 内部循环状态：本地桌宠的实验方向

目标是测试：少读文字历史时，保留模型内部状态能否帮助延续熟悉的语气与相处方式。本仓库没有实现状态导出、修改推理引擎或完成实验；不能把“固定大小状态”写成“永久人格记忆”。

## 已知结构与尚未证明的部分

[Qwen3.8-27B 官方模型说明](https://huggingface.co/Qwen/Qwen3.8-27B/blob/main/README.md)列出的结构为16组“3层Gated DeltaNet＋1层Gated Attention”，共64层。循环部分有状态，模型同时也有完整注意力层。原始[Gated DeltaNet研究](https://research.nvidia.com/publication/2025-04_gated-delta-networks-improving-mamba2-delta-rule)支持高效状态更新，不证明清空其他上下文后性格必然长期稳定。

保留隐状态意味着过去仍以另一种形式参与计算；它不是零历史，也不是模型权重已经学习了某个用户或性格。固定容量仍可能覆盖、干扰或遗失信息。性格和具体事件未必可从状态中分离，不能承诺只留下性格、恰好忘掉细节。

## 先验证可恢复，再试部分清除

- 首先在固定模型、量化、后端与模板下，导出并恢复推理引擎实际需要的完整状态，核对连续生成与恢复生成是否一致。版本指纹包含模型、量化、tokenizer、聊天模板、缓存布局和后端。
- 混合架构可能还需要卷积状态、完整注意力KV、位置和序列元数据。只保留循环层并清除其余内容是独立改造，不假装已有标准API；不能拼接不一致的分支状态或任意重置位置。
- 普通托管聊天API通常不提供这类原始状态读写能力；优先在明确支持状态操作的本地引擎实验，接口以实际版本为准。二进制快照仍需要持久存储和设备资源，不能说完全没有外部存储开销。

## 四组对照

在相同模型、采样设置和新用户输入下比较：全新状态且不重放人设；仅恢复循环状态；完整状态恢复；当前短人设＋连续性摘要方案。把默认模型本身的口吻与用户形成的人格变化区分开。

先做少量可复现脚本，再测试跨日、重启、大量无关对话、情绪变化和明确纠正。分别量化角色一致性、细节正确率、错误共同经历、恢复耗时、显存/内存及总输入输出。相同随机种子有助于控制，但不同后端未必逐token完全一致，不能据此直接宣称失败或成功。

## 与可用记忆方案的关系

当前性格、近期状态与细节仍按[连续性设计](persona-continuity.md)保存；事实可追溯、原文完整归档、[主动联想](proactive-memory.md)受许可和预算限制。循环状态只是候选增强层，不代替来源、纠正、删除和原始档案。

状态可能含已删除或限制使用内容，不能靠删一条数据库行就宣称清除。应从无该信息的安全检查点重放获准内容，或重置状态；无法完成时禁用该快照。升级后不能兼容恢复就使用短状态回退，而非让旧二进制覆盖新角色。

验收以前，README只能说“研究方向”，不能宣称零提示词永久记忆、节省百分比或已经兼容DSH。
