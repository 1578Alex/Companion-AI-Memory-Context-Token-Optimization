# 向量关联、时间衰减与 Top N（v0.3）

一句话说：**先找这次聊天真正相关的事，再把有限空间留给最需要的几条。旧事不会因为年代久远就失去检索资格，角色的性格也不会和普通事件一起竞争出局。**

这是待实现的可选扩展，配套[配置](../config/vector-ranking.example.json)和[验收场景](../examples/vector-ranking-scenarios.json)。向量模型、阈值、权重和半衰期都是工程初值，尚无真实陪伴对话测试结果；不能把这些公式称为人脑模型或感情测量。

## 1. 给事件一个“意思坐标”

事件元仍是有原文来源的一条事件卡。例如“在西安旅行时买了胶片相机”，它保留时间、地点、人物、物品、话题和来源 ID，另增加语义向量。用户说“那台拍胶片的机器”，即使没用“相机”两个字，也可以找到相关候选。

每条事件的向量描述由宿主保存，建议包含：

| 字段 | 用途 |
| --- | --- |
| `embedding_ref` | 指向宿主向量存储的引用，不是把数组写进提示词 |
| `embedding_model` / `embedding_revision` | 精确记录生成模型与版本 |
| `embedding_dimension` / `embedding_normalized` | 向量维度与是否单位化；比较前校验 |
| `embedding_content_hash` | 对应经过来源核验的事件文本版本，防止更正后仍使用旧向量 |
| `memory_id` / `source_refs` | 指向同一事件与原始对话；多种索引不复制原文 |

向量表达的是文本含义，不是记忆的重要性或“感情有多深”。一条事件没有永久不变的“关联程度”；每次用**当前用户问题及有限的有效近期指代**生成查询向量，再和候选事件比较。不计算全库事件两两之间的关系，不把整个档案发送给模型生成查询。

同一模型、版本、维度且单位化的向量，可计算 `S = clip(cosine(query, event), 0, 1)`。负相似度按 0 处理；`S` 只是排序量，不是置信概率。不能比较不同嵌入空间的数字。

## 2. 热度和当前关联度，分工不同

[基础设计](design.md)中的 `heat = 0.45F + 0.35R + 0.20O` 继续决定普通记忆的热候选资格和渐进冷却。向量分数不能把冷库直接变成常驻上下文，也不能刷新用户提及时间。

向量扩展只替换**同一优先级、同一事件子额度内**的普通事件排序。权限、有效性、用户限制、当前相关性、当前未完事项的必要紧凑信息、连续性类型保留和预算规则在先。词法或语义上与本次问题无关的事情，不能靠“昨天刚提过”进入请求。

```text
F = min(近30天去重并执行每日上限后的有效用户提及数 / 6, 1)
R = 2 ^ (-距最近一次有效用户提及的连续天数 / 7)
O = 1（用户确认进行中，且未到复核期限），否则 0

hot_score = 0.65*S + 0.20*R + 0.10*F + 0.05*O
```

这不是在原 heat 上重复加一份时间分，而是独立的请求内排序器；向量排序可用时，原 heat 负责候选资格与迁移，降级时恢复基础热排序。`R` 使用最后一次有效用户提及，不是事件发生时间、向量生成时间或检索时间。一次回忆查询、助手复述、重试和摘要不更新该时间。时间按连续时差计算，零点、重启和换会话都不会重置。

示例语义门槛为 `S >= 0.55`，需要按所用模型校准。来源明确、符合当前问题的精确词法/元数据命中保留独立路径，不因没有向量或低于这个语义门槛而被否决。不同路径的不可比原始分数不能直接相加；无可靠可比向量时使用下述降级排序，不伪造一个 S。

## 3. 冷库找旧事，不用“越新越好”

用户问“你还记得当年在西安买相机那次吗”，先获得原有用户线索许可，再用西安、购买、相机等索引缩小范围。**十年前的事件可以排在第一位；它的年代和最近提及时间都不产生衰减扣分。** 昨天聊过的不相关事情先被排除。

```text
cold_score = 0.80*S + 0.20*C
```

`C` 是当前用户线索的可核验匹配度：对用户实际提供、能定位的类型、时间、地点、人物、物品、话题、明确事件名或原文引句逐维核对，已验证匹配为 1，未知为 0，取这些维度的平均。经核验的同义词或地点层级匹配也可为 1，不能由模型猜测补齐。`C` 不是概率；没有足以定位的线索时应停在线索门控，而不是用 0 分开启全库扫描。

用户明确的条件是前置过滤，不是可以用高语义分抵消的扣分项。明确冲突的记录排除；“2016年西安那次”查事件发生时间，不能用最近聊天时间代替。精确年份下时间未知的记录不能当确定命中，可在未命中后询问是否放宽；“当年”不擅自转换成年份，只有地点也可检索。没有提供的维度不作为缺项扣分。以上规则沿用[逻辑分区](cold-storage-index.md)。

冷排序禁止使用事件年龄、距上次提及时间、频率或热度作为加分、门槛、同分裁决或预先截断条件。先按下文的强精确匹配组，再按组内分数排序；相同分数按稳定 ID 排序。准确的旧事不会因为时间衰减而被压下去；近似索引、标签缺失或信息歧义仍可能导致未命中，因此这里不承诺每次都能找到。

## 4. 有限候选，再选 Top N

1. **先检查范围。** 按 owner、scope、status 和用户限制筛选；冷检索必须有当前用户线索许可。可在索引层预过滤，返回正文前再次检查；不让向量绕过门控。
2. **有限的两条检索路径。** 在授权范围内，语义索引与元数据/词法索引各最多返回 12 个内部候选。宿主限制索引计算量与超时；不是每个地点或分区各取 12 条，更不是全库两两计算。索引内部探测不是额外的模型调用，也不自动授权读所有正文。
3. **融合，不偏新。** 两条路径最多形成 24 个内部引用，按 ID/来源去重，交给正文选择阶段的候选**全局最多 12 条**。先选经过证据核验的 `verified_strong_exact_match` 组，再选普通候选；组内按 cold_score 或冷降级规则排序。强精确指用户给出的明确事件 ID、可唯一定位的原文引句，或至少两个独立且有区分度的用户线索维度全部匹配、没有冲突；单一宽泛城市/话题、C=1 本身均不足。强精确组在融合限12条及最后的冷 Top N 中保持优先，不能仅因 S 较低被较高语义的普通候选挤掉。强精确超过12条时标记 `truncated=true`，按规则返回极少候选并询问新线索，不能把 Top 1 冒充唯一答案。不得在语义检索前先取“最近12条”，也不得把两个列表各12条交给主模型。冷候选含缺失或不兼容向量时，全批统一使用确定性冷后备排序（强精确组优先，再线索匹配度、同一规范的宿主词法分、稳定 ID），不把缺失向量按 0 分排到底，也不混排向量分和词法分。强精确优先不能越过权限、明确过滤条件或歧义核验。
4. **核对与少量输出。** 来源、否定、时间和身份核对之后，同一事件只注入一份，不能用三条近义摘要填满三个槽位；同一话题普通热事件最多 2 条，不同时间发生的不同事件不能误合并。有多个无法判定的事件时按已有规则展示少量候选卡，让用户补线索，不把 Top 1 当作已确认答案。
5. **预算里的 Top N。** N 是上限，不是必须凑够。热记忆最多 8 条 / 960 tokens，冷召回最多 3 条 / 480 tokens，标签、来源和封装也计量。先用合格短摘要，仍不够则减条目；不得截掉否定或事实限定。按相应排序从高到低选择能够完整容纳的记录，超大条目可被后面的合格短记录替代并记录原因。空槽不借给其他桶，最终只给主对话模型必要文字，不给向量、全目录或全部候选。

热排序只扫描有限的 hot 候选池（最多64条），无需为普通问候查询冷索引。冷库的向量与词法路径属于同一次有界检索流程，不借机自动放宽条件、多轮追查。近似向量搜索给出的是候选中的 Top N，不声称找到了整个档案的数学全局最优。

## 5. 性格和近期状态有自己的位置

虚拟陪伴的连续感不能只靠事件排名。稳定性格底色仍在角色前缀；启用[连续性扩展](persona-continuity.md)时，hot 960 tokens 分成：

| 内容 | 独立额度 | 向量事件排名能否挤掉 |
| --- | --- | --- |
| 当前性格、相处习惯与近期状态的连续性记录 | 1条 / 320 tokens | 不能；恢复当前已提交版本 |
| 近期事件细节 | 最多3条 / 320 tokens | 在本子额度内选择，保留必要的近期接续锚点 |
| 当前话题事实 | 最多4条 / 320 tokens | 在本子额度内选择 |

三部分合计仍最多8条/960 tokens，不互相借额度、跨部分去重。状态记录按其类型例外选择，不参与普通事件的相似度、heat、14天闲置冷却或候选池淘汰；它也不能夹带一堆旧事绕过冷库规则。

重启或第二天第一条回复前，先恢复角色版本一致的当前状态。关系熟悉程度和慢变风格不会因为新的一天回到初识；短期情绪按连续时差缓慢靠近当前相处基线。向量更新、Top N变化、一次旧事召回都不能重写性格。情绪的自然变化可以保留，但不以“逼真”为理由编造共同经历或把旧事强塞进每句话。

## 6. 缺失、更新与成本

- **没有向量仍能找。** 先保留原有关键词、别名与分区索引作为后备；不可用、缺失或版本不兼容时显式标记降级，同一批候选统一切换，不混排不同分值。热事件先按原有相关性、任务连续性、类型与子额度规则筛选，再恢复基础同级顺序：heat 降序、最近有效用户提及降序、ID 升序；冷事件保留强精确优先组，再按 C、统一词法分、ID 排序，仍不使用新近度。不能清空准确的精确命中、删除档案或扩大权限。
- **只处理增量。** 新增/更正且来源明确的事件文本才生成或更新向量。检索读取不重嵌入全文；用户输入查询向量按一次有效查询计算，可按不越过权限的短期缓存复用。查询缓存到期与撤权后清理。
- **版本不能混用。** 配置具体模型后才能宣称向量可比较；维度、模型或版本不一致时拒绝直接比较。模型迁移在宿主受控预算内增量/离线建新索引，核验后原子切换；期间词法路径继续可用，原文不动。禁止在切换期把两种空间的分数拼成一个榜单。
- **更正、删除立即有效。** 默认检索排除旧版本，失效向量、索引、派生摘要和查询/结果缓存一并失效；删除还需清理对应向量数据与原文。历史记录是否可查仍按原有有效性与用户许可规则，不因留下一个旧 embedding 就复活。
- **计总账。** 本地索引计算不消耗主对话模型输入 token，但嵌入、重排、存储、延迟和任何辅助模型费用都要记录。短主请求不等于总费用已经降低。

验收重点是：旧事不被时间衰减埋掉、无关近事不能靠新鲜度挤进来、同一个角色跨天有延续、最终输入确实有上限。场景文件中的 expected 只是要求，尚未运行真实模型评测。
