# 主动回忆与独立反思区（v0.4）

希望她能接住“我今天好累”，也记得上次聊到哪里；想起了不等于一定说，说出来也不能把猜想当成事实。

这是待实现的可选扩展，配套[配置](../config/proactive.example.json)和[案例](../examples/proactive-scenarios.json)。没有接入运行时，也没有测得真实感、准确率或节省比例。默认仍使用[基础设计](design.md)的用户线索模式，不能只复制提示词就宣称启用了主动记忆。

## 1. 先决定能否查，再决定说不说

只有用户明确开启主动陪伴模式，并选择允许联想的范围后，当前已验证身份的用户互动才可提供情境或情绪入口。“累”可以让宿主在获准的日常工作、作息等范围里找候选；它不证明今天仍是加班。没有可区分的情境或相关证据时，直接回应当下，不扫描全库找话题。

宿主先执行 owner、scope、有效性与用户限制，再在限定主题和类别中执行一次有界检索。用户要求“问到再说”的条目不能被情绪触发读取，明确回忆线索仍按基础规则处理；敏感事项必须有明确线索，不能由推断的情绪开启。定时器、助手自言自语、工具返回和截图都不能冒充真实用户入口。关闭扩展后立即恢复原门控。

三步分开：

1. **找相关记录。** 沿用[向量扩展](vector-ranking.md)的语义、精确线索、日期过滤与去重，融合后最多12个候选；情绪匹配只是相关信号。旧事不因事件年龄降分，当前事实是否仍适用则单独核对。
2. **核对能相信什么。** 确认原说话方、原时间、事实状态和来源。用户说过“上周加班很累”只证明当时的陈述，不证明今天的原因。没有出处、已失效、仅来自反思的候选不能当成真实经历。
3. **判断 use / ask / silent。** 有明确当前依据且有帮助时自然使用；只有历史关联时以轻问确认；证据弱、多个原因冲突、已重复提过或不适合此刻时沉默。沉默表示不提旧事，仍可正常回应当前消息。

例如（虚构）：

> 用户：好累。
> 她：又是工作上的事吗？上次你说那阵加班挺累的。

这是一句有来源的试探，不是“你今天又加班了”的断言。用户说“不是”后，立即修正当前理解，不继续围绕加班追问。主回答一次生成时判断表达，不为每个候选单独调用大模型；检索授权和限制仍由程序执行，模型只提出表达动作。

## 2. 主动一点，但别反复翻旧账

主动许可绑定触发它的用户交互、用户身份与话题；最多沿用5个后续用户交互或30分钟，取先到者，换话题立即退出。助手回复、空闲时间和“继续”不无限续期。每个用户/主题在一次主动检索尝试后冷却24小时；沉默也不允许后台不断重试。新的明确回忆线索可以按基础规则查询，不受主动冷却影响。

用户拒绝该联想或要求停止后，停止这个主动主题，直到用户重新主动提及或明确解除限制。“以后别主动提”还需写入相应 recall_only 限制，不能仅依赖一天的冷却。读取、猜测、提起、沉默、重试和自动摘要均不增加有效提及、热度或关系熟悉度；只有真实用户实质确认或补充才可能按基础规则计数。

## 3. 真实经历与自己的想法分开

独立反思区使用 `kind=reflection` 或 `kind=hypothesis`，不是事件库的别名，也不是隐含推理日志。这里存放有限、可查看的角色观察或猜想，例如“下次他愿意聊时，可以问问工作近况”；不是“他今天加班了”。

每条反思至少有：`id`、`owner_id`、`scope_id`、`kind`、简短内容、`source_refs`、`generated_at`、`valid_until`、`status` 和派生来源依赖。未证实写为 `unverified`，更正为 `superseded`，删除为 `deleted`；过期退出可见集合。示例有效期最多7天，待实测校准。反思自身“真实”只表示系统曾生成过这条想法，不代表想法描述的外部事情成立。

反思只能来自宿主已授权提供的少量近期真实事件和当前锚点。后台不得自行搜索冷库；想处理更久的事件，需等用户在当前互动中合法唤回后形成新的、获准的近期输入。不能拿一条反思再次当证据制造另一条事实，反复想起不提高可信度，不自动强化长期性格或关系。用户后来确认了某个内容时，从该次用户原文新建或修正事实，旧猜想仍保留自己的来源类型，不能直接改成“亲历事件”。

存储期限与本轮可见许可是两回事。旧事被合法召回，不会因此变成新的近期事实。后台输入和每次注入反思时，都重新检查原始来源的权限、当前话题与许可期限；依赖冷库的内容在原许可过期或换话题后不可见，除非当前用户互动取得新的有效许可。最多7天只是反思记录的保存上限，不能给旧事续上7天的调用权。

来源被更正、限制或删除时，同步撤下依赖它的反思、摘要、向量和请求缓存，重新核对其余派生状态。不能为了保持情绪而复活失效内容，也不能把反思偷偷复制到常驻性格记录。

## 4. 保住性格与近期细节，额度不变

[连续性扩展](persona-continuity.md)的性格底色、相处基线、近期情绪来由和未完事项继续独立保留。短期情绪可以自然缓和，新好消息可以改变语气；过夜不把关系重置，也不把未解决事项写成解决。主动召回与反思不能挤掉当前状态或改写角色底座。

- 记忆快照仍最多1600 tokens：固定160、hot960、临时召回480，不互借。
- hot仍为状态320/1条、近期细节320/3条、话题事实320/4条，总最多8条、同主题普通事件最多2条。
- 一次主动输出最多2条事件；反思不是每轮默认注入，可选最多1条、含封装最多96 tokens。事件、候选卡和反思**合计最多3条/480 tokens**，反思从这480里扣，不能另开无限桶。
- 同一事件在近期窗口、hot、召回与反思引用中去重；来源指针可以留下，但正文不重复。反思的96上限不保证能放下一切；放不下就不注入，不截掉否定或来源限定。

## 5. 后台别空转

示例后台预算（未经真实用户测试）：

| 项目 | 上限 |
| --- | ---: |
| 每日维护调用尝试总数 | 2次，失败与重试也算 |
| 每次总输入 / 输出 | 2000 / 300 tokens |
| 每日总输入 / 输出 | 4000 / 600 tokens |
| 两次维护尝试最小间隔 | 6小时 |
| 每次候选反思变更 | 2条 |

只在有新完成互动时排队，合并短时间内的新增事件，空闲时执行；没有新事件直接跳过。日界按 Asia/Shanghai，6小时间隔按连续时差，不能午夜立即再跑。模型、嵌入、分类、重排和重试都从同一个维护调用与token账本扣：如果一次嵌入占掉一个调用，不能再把它说成“反思之外免费的一步”。本地纯规则与索引运算也记录时间与计算成本，但不是模型调用。

发送前用可靠计数器预留输入和输出额度，含提示词、状态、来源与协议封装；设置输出硬上限，结果按供应商实际 usage 核账。余量不足不发起，失败用量未知时按已预留额度保守占账。不能可靠计数或限制输出时，禁用后台模型维护，保留规则归档；不能用字符估算宣称硬预算已通过。主对话、在线检索嵌入与所有辅助费用另记同一互动总账，不能因为不在后台额度里就漏报。

宿主持久保存每天的调用/输入/输出预留和已用量、每维度水位、队列幂等键、最近尝试时间，并用单worker锁或原子版本检查。重启、并发、超时和同一互动重试不能清空账本或重复消费源事件。关闭模式、撤权、删除时取消相关排队任务。主动记忆不要求实际安装新的定时服务。

## 6. 合并是压缩，过期是管理当前状态

合并只处理同一事件或事实的重复表示，不把两次“很累”强行合成同一原因。保留说话方、日期、否定、不同原因与来源；合格摘要应从原始事件产生，不能反复总结猜想得到“真实经历”。高重要事件可保留独立细节，但也受权限、更正和预算约束。完整原文继续归档，明确删除例外。

时间仍用于判断当前状态是否适用、进行中事项何时复核和反思何时失效；不用“合并”替代全部时间管理。老事件可以按线索找到，旧工作压力却不自动解释今天。案例见[主动案例](../examples/proactive-scenarios.json)，expected都是待执行要求，不是已通过的运行测试。
