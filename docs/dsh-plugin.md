# 做成 DeepSeek Harness 记忆插件

**English: [DSH memory plugin plan](dsh-plugin.en.md)**

可以做。这里说的是 **DeepSeek Harness（DSH）**，目标是让使用它的本地陪伴角色接得住昨天的聊天：性格和近期细节放在手边，旧事存好，需要时少量找回来。

**现在完成的是接入调查和方案，仓库还没有可安装的 DSH 插件。** 没有修改或安装到用户的 DSH，也没有跑过真实对话测试。把提示词粘进去，不能代替存储、检索和实际请求预算。

## 哪些能力已有入口

| 要做的事 | 已核对的宿主能力 | 本项目状态 |
| --- | --- | --- |
| 增量读取完成的对话 | `sessionProjections`、已提交会话事件及水位 | 待实现提取与恢复 |
| 原文、事件卡、索引和反思分开保存 | Host 侧 `storageDomain` 与持久化后端；会话原始日志继续保留 | 待设计具体存储表和迁移 |
| 保留性格、相处方式、近期状态 | 按角色作用域注册 `systemPrompt.section()`，必要时用 `agent.inject()` 加入可回放内容 | 待实现限额、渐变与去重 |
| 用户线索唤回、可选主动回忆 | Host 侧先判权限和范围，再调用有界检索服务 | 待实现，不靠模型自行遵守权限 |
| 判断提起、轻问还是沉默 | 将有限候选交给主回答，同一次生成选择表达动作 | 已有提示词，待运行验证 |
| 真正减少旧历史输入 | 官方 `compaction` 服务和可替换后端，在日志里记录摘要替换，原始事件保留 | 待接入与请求验证 |
| 防止模型绕过冷库入口 | 角色作用域的 `tools.restrict()`、`tools.guard()` | 待检查所有可读档案的工具路径 |
| 后台整理及次数限制 | Host 插件生命周期、计时器、存储；`inject()` 不主动唤醒，`followup()` 会唤醒 | 待实现持久账本和取消机制 |

这说明可以开发 Host / Cordis 插件。只做一个 MCP“搜索记忆”工具也能提供检索，但它通常不能独自控制 DSH 原有历史、通用文件工具和后台调用，所以不能仅凭 MCP 接通就宣称省下了上下文。

## 接进去以后，一轮聊天怎么走

1. 用户发来消息。宿主确认是哪个用户、哪个角色和哪个话题，先应用禁提、删除和“问到再说”等限制。
2. 从热记忆拿出性格与当前状态、近期细节和本轮相关事实。普通热事件按向量关联、新近度、有效提及排序，角色底色与当前连续性另行保留。
3. 有明确回忆线索时查冷库；用户另外开启主动模式后，也可从本轮情境进入获准的主题。地点、日期、人物、物品和话题先缩小范围，再返回少量候选。冷库不按年代惩罚旧事。
4. 主回答判断自然使用、轻问确认或不提旧事。“上次加班很累”只能支持“这次也是工作上的事吗？”，不能直接变成“今天又加班了”。
5. 发出请求前，程序执行去重、完整历史减负和总预算检查。完成后归档原文，按新提交事件的 ID 与水位更新记忆；助手自己的复述不增加热度。
6. 有新完成互动才排队整理；没有新内容就跳过。独立反思区可以留下有来源、会过期的猜想，不能把猜想写成用户真实经历。

规则沿用[基础设计](design.md)、[连续性](persona-continuity.md)、[向量排序](vector-ranking.md)与[主动回忆](proactive-memory.md)，不为 DSH 再开一套更宽松的额度。

## 两个容易踩的坑

**加了记忆，不等于减少了历史。** DSH 请求从会话日志构造，模型调用时消息已冻结。`agent/pre-step` 处理当次进入的消息，不是任意删除整段历史的接口；`agent/request` 和 `llm/stream` 也不能用来偷偷重写它。旧历史需要走官方压缩机制，保住工具调用配对、锁和回放记录。

`agent.inject()` 加入的内容还会成为后续历史。每轮最多加 1600 tokens，连续加十轮仍可能越积越多。实现必须清理已被替代的旧召回和快照、限制近期窗口，并检查**最终实际发给模型的完整请求**。系统提示词、工具定义、当前消息及运行中的工具协议另行计数；反复变化的提示词也可能影响缓存。

**计时器不等于免费思考。** 不定时扫描全冷库，也不定时唤醒主角色去“想点什么”。后台仅处理获准的新完成事件，在空闲时合并执行。示例上限为每天 2 次尝试、最少间隔 6 小时、每次输入/输出 2000/300 tokens；失败、重试、嵌入和重排都按配置共用额度。

存储接口支持单次 KV 调用的原子持久化，不代表多个记录自动构成事务。先持久预占额度再发送，串行执行或使用可核验的版本检查，保存幂等键、水位和上次尝试时间。重启和午夜不能清掉限制。DSH 自带 token-meter 对文本采用近似估算，不能用它冒充中文的硬计费上限；没有可靠计数或输出上限时，关闭后台模型调用，保留规则归档。

## 第一版范围

先做一个角色、一个用户范围的 Host 插件，加独立存储和有限检索，不接管其他角色。默认按用户线索检索，主动模式单独开启。记忆块仍为固定 160、热区 960、召回 480 tokens；主动候选、事件和可见反思共用最后的 480，不额外叠加。

保护性格底色、当前相处方式和未完事项，近期状态按来源渐变；长久不提的事件逐步收成摘要再退出活跃区。真实原文与来源留底，明确删除例外。反思区独立、可查看、有期限，来源被更正或删除时撤下其派生内容。

存储先采用当前配置已有的持久后端；只有规模和查询性能测出来需要时，再考虑 PostgreSQL / pgvector。截图里用了 PG，不代表本插件也必须先安装数据库。

通用文件、搜索、Shell、子代理或其他工具若能读到完整冷库，都可能绕开检索预算。需要逐条核对并在该角色范围限制；一个检索工具上的限制不构成整台电脑的文件隔离。

模型内部循环状态另见[实验说明](recurrent-state-experiment.md)。本调查没有发现可让 DSH 的 DeepSeek API 导出、恢复 Gated DeltaNet 隐藏状态的接口，不将它列为本版插件能力。

## 何时能说“插件能用”

- [ ] 检查实际配置和运行接口，明确支持的 DSH 版本；缺少服务时停止该功能并给出原因。
- [ ] 完成 bundle、配置、存储迁移与撤销方式，安装后确认功能真正生效。
- [ ] 跨会话、重启与跨午夜，性格基线、近期细节、水位和后台额度保持一致。
- [ ] 看最终请求验证：旧原文和过期召回不再重复发送，工具协议仍完整，记忆与近期窗口各自受限。
- [ ] 用久远地点/时间/物品线索能找回原记录；弱情绪不被当作原因，主动拒绝和“问到再说”生效。
- [ ] 更正、删除和撤权同步处理反思、摘要、向量及缓存，不能从旧日志或备份偷偷恢复到可见记忆。
- [ ] 后台空闲无新事件为零调用；并发、失败、超时和重启不突破预占额度。
- [ ] 把提取、检索、嵌入、后台、重试和缓存成本都计入对照，公布测得结果。

以上目前都是待完成验收项，尚无真实节省比例或“永不失忆”的测试结论。
